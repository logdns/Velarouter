# 会合与直连：不需要部署服务器

> 目标：打开 Velarouter，屏幕上就有 **联机码 + 临时密码**；另一端在任意网络输入这两个值即可连上并操作。
> 本文件说明它是怎么做到的、什么时候会失败、以及如何换成自己的服务。

## 1. 为什么需要“会合”

两台电脑各自在路由器后面。能上网页说明**出站**通，但不等于别人能**入站**找到你。
要建立点对点连接，双方必须交换一次“我在这里”的地址。这个交换就叫会合（rendezvous）。

常见做法是厂商自建服务器（向日葵、UU 远程都这样做）。Velarouter 默认不要求任何人先部署服务器，
做法是：**联机码本身就是会合密钥**，双方各自算出一个 MQTT 主题和一把 AES 密钥，在一个公共
MQTT-over-TLS 服务上碰头。

```
被控端                                          公共 MQTT 服务                        主控端
  │ 主题 = f(联机码)、密钥 = HKDF(联机码)             │                                  │
  │ 候选地址 = 内网网卡 + STUN 反射地址  ───────────►│◄──────── 同样的候选地址           │
  │◄──────────────── AES-GCM 加密的候选地址表 ───────│─────── AES-GCM 加密的候选地址表 ─►│
  │ 向主控端候选地址发包，打开本机 NAT 映射           │                                  │
  │ ═════════════ 双方在同一 UDP 端口上 QUIC 握手 ═══════════════════════════════════►│
  │ ═════════════ VRP：密码 → 双向证明 → 会话密钥 ═══════════════════════════════════►│
  │ ═════════════ 画面、键鼠、剪贴板、文件（点对点） ═══════════════════════════════►│
```

会合服务只看到：某个哈希主题下的一段**密文**。它不知道联机码本身，解不开地址表，也永远拿不到密码和画面。

## 2. 三个阶段

### 2.1 码是本地的

- 首次启动生成 12 位数字（约 40 bit），之后保存在本地配置里，重启不变；临时密码每次启动重新生成。
- 生成码**不需要**公网 IP、不需要登录、不需要填服务器地址。
- 局域网码（`VR-…`）完全不走网络：码里直接编码了内网地址与端口。

### 2.2 会合（< 2 秒，通常）

| 步骤 | 说明 |
|---|---|
| 建 UDP 套接字 | 优先固定端口 `34793/UDP`，被占用时用临时端口 |
| 收集候选 | 内网网卡地址（排除回环/link-local）+ STUN 反射地址（Cloudflare / Google / Bilibili） |
| 路由器映射（尽力） | 后台向 IGD 申请 300 秒 **UDP** 映射，成功则追加「公网 IP:外部端口」候选；不修改防火墙、不申请永久租约，失败即跳过 |
| 连接会合通道 | 逐个尝试公共 MQTT-TLS 端点，连上即登记“在线” |
| 发布/订阅 | 每 0.7–1.5 秒发布一次加密候选表；收到对端后立刻回发一次，避免订阅时序丢包 |

### 2.3 打洞 + QUIC

- **被控端**：得知主控端候选地址后，向每个地址发 1.3 秒探测包，打开本机 NAT 映射，然后把同一个
  套接字交给 QUIC（服务端）。
- **主控端**：拿到被控端候选后等 0.7 秒，然后对所有候选并行发起 QUIC 连接，第一个成功的即采用。
- QUIC 用临时自签证书；证书不承担身份，身份由 VRP 握手（密码进 HKDF salt，双向 HMAC 证明）确认。
- 成功后 `ALTER` 不需要中继：画面、键鼠、剪贴板、文件全部走这条 UDP 直连。

## 3. 什么时候会失败（以及为什么）

| 情况 | 结果 | 说明 |
|---|---|---|
| 两台电脑在同一局域网 | **最快**，直接命中内网候选 | 或者直接用 `VR-…` 局域网码 |
| 一方全锥形/受限锥形 NAT | 可以直连 | 家庭宽带常见情况 |
| 双方都在**对称 NAT / CGNAT** 后 | 若路由器不支持 UPnP/PCP/NAT-PMP 则打洞失败，提示“对方没有响应” | 没有中继时这是物理限制；可手动做端口映射（`34793/UDP`）或使用 VPN |
| 公司/学校网络封 UDP | 失败 | 只放行 TCP 443 的网络无法点对点 |
| 公共会合服务不可达 | 状态显示“会合中断，正在重连”，局域网仍可用 | 可换自建服务 |
| 一端正在被别的会话占用 | 对方提示“没有响应” | 一个被控端同时只服务一个会话 |

**“能上网页”只代表出站可用。** 首页把这两件事分开显示：`互联网 · 可访问` 是出站检测，
`已就绪` 才是“会合通道在线、别人可以凭码找到你”。

## 4. 自建会合服务

任何支持 MQTT over WebSocket 的 broker 都行，例如 mosquitto：

```conf
# mosquitto.conf
listener 8084
protocol websockets
allow_anonymous true
```

```sh
mosquitto -c mosquitto.conf -d
```

前端放一个 TLS 反向代理（443 → 8084），然后在 Velarouter「设置 → 网络 → 会合服务」里
填 `wss://your-host/mqtt`，两端填同一个地址即可。也可以只在打包时内置：

```sh
VELAROUTER_BROKERS="wss://your-host/mqtt" bash scripts/package-macos.sh
```

命令行等价写法：

```sh
velarouter agent --broker wss://your-host/mqtt
velarouter connect --code 123456789012 --password 123456 --broker wss://your-host/mqtt
```

关闭互联网联机（纯局域网模式）：`--broker off`。

## 5. 安全边界

| 属性 | 结论 |
|---|---|
| 会合服务能否看到联机码 | 不能。主题是 `SHA-256("velarouter-meet-v1|" + 码)` 的前 15 字节 |
| 能否看到地址表 | 不能。AES-256-GCM，密钥由码派生，AAD 绑定主题 |
| 能否看到密码/画面 | 不能。密码只在 VRP 握手里用，画面在 QUIC + VRP 双重加密内 |
| 猜中码的后果 | 能看到候选地址、能发起连接尝试；**无法通过密码验证** |
| 重放 | VRP 用每次会话随机的 session id 与双向 proof；控制通道计数器单调 |
| 中间人 | 没有密码无法伪造 proof，QUIC 证书被刻意跳过校验但身份不依赖它 |

码只有 40 bit，是**临时分享凭据**而不是长期口令。需要长期无人值守访问时，用长密码（≥12 位）
或固定 `--internet-code` 并在分享后轮换。

## 6. 端口与协议清单

| 用途 | 默认 | 协议 |
|---|---|---|
| 被控端 Web / 局域网会话 | 34789 | TCP（HTTP + WebSocket） |
| 会合 + QUIC | 34793 | UDP（可回落到临时端口） |
| 会合通道 | 443 | WSS（MQTT 3.1.1，subprotocol `mqtt`） |
| STUN | 3478 / 19302 | UDP（仅出站） |
| 局域网码 | 任意 | 无网络请求 |

## 7. 排障顺序

1. 被控端首页是否显示 **已就绪**？不是的话看状态行文字，等 10 秒重连。
2. 主控端输入的是否是**最新**的 12 位码？码在重启后不变，但密码每次启动会变。
3. 同一 Wi-Fi 先用 `VR-…` 局域网码确认键鼠可用，再测跨网。
4. Mac 被控端是否授权了**辅助功能**（不是屏幕录制）？否则只能看画面。
5. 双方是否都是“大内网 / 公司网”？换手机热点做对照实验。
6. 仍失败：在设置里换成自建会合服务，或使用双方都可访问的 VPN。
