## 1. 公网 TLS：签发和使用是两条证据

在受托服务器按[部署说明](../DEPLOYMENT.md)部署。保留 Caddy 日志中对应域名本次 **ACME challenge 和证书签发成功**的时间与签发机构；不要删除现有生产证书卷来强制测试。已缓存证书只能记为“证书可用”；可用所有者授权的新测试子域名验收首次签发。

从**另一网络**运行下列检查（替换域名）。不得使用 `-k`、自签根或 staging CA 代替公网受信任证书。若有 CDN 终止 TLS，边缘证书不能证明源站 Caddy 签证。

```sh
domain=signal.example.com
curl --fail --show-error "https://$domain/v1/health"   # JSON: ok 为 true
openssl s_client -connect "$domain:443" -servername "$domain" </dev/null 2>/dev/null |
  openssl x509 -noout -subject -issuer -dates -fingerprint -sha256
curl -sS -o /dev/null -w '%{http_code}\n' "https://$domain/v1/devices"  # 不带 token：401
```

## 2. 桌面与权限：两台机器交换角色

1. 使用无敏感资料的测试账户。在两台图形会话终端记录 `uname -m`、`echo "$XDG_SESSION_TYPE $XDG_CURRENT_DESKTOP"`、发行版和安装包 SHA-256；至少一端为原生 Wayland 会话，而非只在 XWayland 窗口测试。不要以 root 运行客户端。
2. 先在同一局域网用 `VR-…` 地址码建立基线。主控端观察被控端时钟/窗口变化，移动鼠标，在临时文本框键入约定短句；由被控端确认内容。交换主被控端重做，分别记录画面、键盘、鼠标。不能以“握手成功”代替这些观察。
3. 在 Wayland 被控端记录桌面、实际授权提示及权限状态。当前版本在主机启动共享时通过 `org.freedesktop.portal.RemoteDesktop` 弹出系统「远程桌面」对话框；记录用户选择的是哪块屏幕、是否打开「允许远程交互」、点「分享」后主控端是否收到「已允许」。先拒绝或关闭开关，确认主控端显示「仅观看」且点击/输入不生效，再让现场用户在本机「设置 → 权限」重新申请并重连验证。授权后分别对原生 Wayland 应用和 XWayland 应用测试输入，并切换主控端屏幕选择，确认只能控制被授权的那一块。没有弹窗、桌面不支持 portal 或只跑在 XWayland 时据实记录为受限，**不能把“画面可见”或“X11 能控”记作 Wayland 通过**。X11 的通过不能替代 Wayland。
4. 用文件窗口选择不同于默认位置的目录；测试文件名带空格和中文。先从 A 上传，再下载到另一个目录，比较两端 `sha256sum`。试一次不存在的路径，确认报错且未写入旧目的地。交换主被控端重复。

## 3. 跨 NAT：区分 HTTPS 可达和 UDP 直连

一台接普通宽带，另一台接手机热点或另一处网络，确认是不同公网出口且没有 VPN / 同网旁路。两端填同一个自建 HTTPS 信令，用 9 位码发起连接，**不要用 `VR-…` 地址码**。记录界面连接方式、首帧、实际输入和双向文件校验；交换角色再做一次。只有观察到 P2P/QUIC 会话和远端实际响应才算直连通过。若只健康检查成功或 UDP 打洞超时，记为未通过，桌面不会自动走中继。

**现场记录格式**：时间（含时区）｜两端包哈希、桌面/角色与网络类型｜操作/授权选择｜预期｜实际/错误｜脱敏日志或截图。请排除密码、设备码、令牌、私钥和私人画面。只通过既有安全渠道安排服务器和图形会话访问，不要把凭据写进此文档。
