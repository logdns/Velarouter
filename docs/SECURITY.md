# 安全说明

## 使用建议

- 只在你有权访问的设备上启用共享。只把连接凭据给你信任的人，不要发到公开群、截图或日志里。持有有效凭据的人可以访问已授权的画面、键鼠及共享文件。
- 桌面端打开即开始共享，打包版默认开机自启。只在需要时共享的话，在「设置 → 设备」关闭自启，用完点击「暂停共享」。
- 不要把桌面监听端口 `34789` 转发到公网。自建信令使用 HTTPS/WSS，保管好服务器的管理员令牌及设备端的 `identity.json`。
- 短密码适合临时配对，不适合无人值守。确需固定密码时，使用密码管理器生成的高熵随机密码；应用还没有每次连接的本地审批或长期设备指纹校验。

## 加密与信任边界

VRP/1 使用临时 P-256 密钥交换、HKDF、双向证明和 AES-256-GCM 保护会话内容。短密码握手不是 PAKE；不能把低熵密码视作强身份认证。浏览器从局域网 HTTP 加载客户端时，也只能在可信网络使用，因为传输加密不保护 HTTP 下发的页面代码。

- **局域网**：主控端直接连接被控端，不需要第三方服务。
- **公共会合**：MQTT 服务转发加密后的地址信息，不转发屏幕。它仍能观察连接元数据，且会合信息的保护依赖联机码；联机码与连接密码不要混用。
- **自建信令**：信令端需要接收配对登记，必须信任该服务器。服务端的加密中继接口不是桌面默认连接失败后的自动回落。

这不是第三方安全认证。已知网络限制见[会合与直连](RENDEZVOUS.md)，协议细节见[VRP/1](PROTOCOL.md)。

## 报告问题

通过 [GitHub 私密漏洞报告](https://github.com/logdns/Velarouter/security/advisories/new) 提交版本、平台、影响范围和复现信息。请勿附真实联机凭据、令牌、私钥或私人画面。
