# Velarouter 介绍

> **近在眼前的远程桌面。**
> 一个二进制，两种网络：内网直连不走服务器，公网中继只传密文。

---

## 1. 它解决什么问题

远程桌面软件通常在三件事上让人失望：

1. **慢**：连自己的电脑要绕地球一圈，明明在同一个路由器下。
2. **重**：为了“全功能”装一个几百 MB 的客户端，附带账号、会员、弹窗。
3. **不确定**：不知道画面经过谁、有没有被记录、服务器能不能看到。

Velarouter 的答案很直接：

| 承诺 | 做法 |
|---|---|
| **简单** | 一个 9 MB 的二进制，`velarouter agent` 就能被控；浏览器打开就能看 |
| **快捷** | 同一局域网内点对点直连，握手 < 5 ms，首帧约 0.2 秒 |
| **迅速** | 静态画面零带宽；变化才编码；输入事件 60 Hz 直达 |
| **可信** | P-256 + AES-256-GCM 端到端加密；中继是哑管道，服务器不是信任根 |

## 2. 两种模式，一条协议

### 2.1 内网远程桌面（默认）

```
┌────────────┐          ws://192.168.1.10:34789/vr          ┌────────────┐
│  主控端     │ ──────────────────────────────────────────► │  被控端     │
│ 浏览器/App  │ ◄────────────────────────────────────────── │  agent     │
└────────────┘      加密 JSON + 加密 JPEG（不经过任何服务器）  └────────────┘
       ▲                                                          ▲
       └──────────── 用户从被控端屏幕读取 6 位配对码 ───────────────┘
```

- 不需要账号、不需要外网、不需要安装服务端；
- 配对码只通过人眼传递，不经过网络；
- 适合：家里连书房、公司连工位、实验室连测试机、展会演示。

### 2.2 互联网远程桌面（默认 P2P，无中继）

安装后自动生成 **联机编码**（9 位）与 **联机密码**；主控端只输入这两个值：

```bash
velarouter connect --signal https://signal.example.com \
  --code 851023857 --password 445566
```

```
punched: local port 55699 → peer 198.51.100.7:57000 (no relay)
first frame after 181 ms: 1920x1080 106404 bytes
```

信令服务器只交换双方观察到的 UDP 地址；打洞后用 **QUIC** 直连，画面与输入不经过服务器。
打不通就明确报错，**不会**偷偷回落中继。细节见 [`P2P.md`](P2P.md)。

#### 需要中继时（可选）



```
        ┌─────────────────────┐
        │  vr-signal（可选）    │  设备注册 / 配对 / 会话撮合 / 中继
        └──────┬────────┬─────┘
               │        │
      ┌────────▼──┐  ┌──▼────────┐
      │  主控端    │  │  被控端    │
      └────────┬──┘  └──┬────────┘
               │ 直连成功? │
        ┌──────┴─────────┴──────┐
        │ 是：局域网 / UDP 打洞   │
        │ 否：WSS 中继（仅密文）  │
        └───────────────────────┘
```

- 信令服务器只做“介绍人”，看不到画面；
- 中继是字节管道，没有解密能力；
- 适合：出差连公司、跨地区连家里的机器、给客户做远程协助。

## 3. 为什么“快”不是玄学

| 环节 | 做法 | 效果 |
|---|---|---|
| 路径 | 同一网段直连 | 延迟 = 交换机一跳（< 1 ms） |
| 传输 | 局域网 WebSocket，无 TLS 二次握手 | 建连 < 5 ms |
| 采集 | 平台原生（DXGI / ScreenCaptureKit / X11） | 5–30 ms |
| 编码 | JPEG 基线（可换 H.264） | 10–50 ms |
| 跳帧 | 16×16 感知哈希，画面不变就不发 | 静态桌面 0 kbps |
| 输入 | 归一化坐标 + 事件直达 | 端到端 < 30 ms（本机） |
| 解码 | 浏览器 `createImageBitmap` / 原生硬解 | 3–10 ms |

实测（macOS / M 系列 / release，1600×900 q60）：

```
首帧            177 ms
帧大小          ~117 KB
静态桌面带宽     0
本机 RTT        1–5 ms
```

> 公网经中继时，延迟取决于两端到中继的 RTT；这是物理规律，不是实现问题。
> 需要更低延迟时，启用 roadmap 中的 UDP/QUIC 媒体通道。

## 4. 五端，一套协议

| 平台 | 主控端 | 被控端 | 说明 |
|---|---|---|---|
| Windows | ✅ | ✅ | DXGI/GDI + SendInput |
| macOS | ✅ | ✅ | ScreenCaptureKit + CGEvent（需 TCC） |
| Linux | ✅ | ✅ | X11 完整；Wayland 经 RemoteDesktop portal 授权后可控制所选屏幕，拒绝则只读 |
| iOS | ✅ | ⚠️ | 系统禁止注入，只能 ReplayKit 只读共享 |
| Android | ✅ | ✅ | MediaProjection + 无障碍/输入法 |
| 浏览器 | ✅ | — | 零安装，WebCrypto + 纯 JS 兜底 |

协议文档：[`PROTOCOL.md`](PROTOCOL.md)。参考实现：Rust、JavaScript、Go 各一套，共用同一组
已知答案测试向量。

## 5. 能力边界（诚实版）

**现在就能用：**

- 实时画面（JPEG）、鼠标/键盘/滚轮/触摸、文本输入
- 双向文本剪贴板
- **文件传输**：列目录、上传、下载、断点续传、SHA-256 校验、路径沙箱
- 多显示器列表与切换
- 局域网广播发现、mini-STUN、UDP 打洞原语
- 远程开机（Wake-on-LAN）
- 配对码 + 端到端加密 + 中继

**正在补：**

- H.264/H.265 硬件编码、UDP/QUIC 媒体、音频
- 终端、文件系统挂载、隐私屏、虚拟按键
- 会话录制、设备身份（TOFU）、配额与审计

详见 [`FEATURES.md`](FEATURES.md) 与 [`OPEN-SOURCE.md`](OPEN-SOURCE.md)。

## 6. 和常见方案的区别

| 维度 | RDP / VNC | 商业远程桌面 | WebRTC 方案 | Velarouter |
|---|---|---|---|---|
| 内网直连 | 可以，但配置繁琐 | 通常仍走云 | 可以 | **默认**，零配置 |
| 协议公开 | RDP 复杂 / VNC 简单 | 私有 | 标准但庞大 | **JSON + 24B 头，公开** |
| 端到端加密 | 取决于部署 | 平台托管密钥 | DTLS-SRTP | **是，中继不可读** |
| 代码可审计 | 开源实现可选 | 否 | 是 | **是（4000 行核心）** |
| 部署 | 需要服务端 | 订阅 | 需要 TURN/信令 | **单二进制，可无服务器** |
| 体积 | 系统自带/轻 | 100 MB+ | 中 | **9 MB** |

Velarouter 不追求在“游戏串流”或“4K HDR 专业场景”上超过成熟商业产品；
它追求的是 **在自己的网络里，用最简单的方式，安全地看到并操作另一台机器**。

## 7. 五分钟上手

### 内网

```bash
# 被控端
./velarouter agent --code 654321
# → 记下屏幕上的 IP 与配对码

# 主控端（同网段）
./velarouter probe --url ws://<被控端IP>:34789/vr --code 654321 --save shot.jpg
# 或浏览器打开 http://<被控端IP>:34789/
```

### 公网

```bash
# 服务器
./velarouter signal --bind 0.0.0.0:34790 --public-url https://signal.example.com

# 被控端
./velarouter agent --signal https://signal.example.com --code 123456
```

### 文件

```bash
./velarouter ls  --url ws://<IP>:34789/vr --code 654321
./velarouter put ./report.pdf --url ws://<IP>:34789/vr --code 654321 --force
./velarouter get --url ws://<IP>:34789/vr --code 654321 --path report.pdf --out ./copy.pdf
```

### 自检

```bash
./velarouter doctor     # 采集、注入、端口、网卡
```

## 8. 安全一句话

**配对码决定“能不能连”，ECDH 决定“连上后谁也看不懂”。**
中继、日志、服务器都不持有会话密钥；配对码错误时双方在证明阶段就断开。

更多：[`SECURITY.md`](SECURITY.md)。

---

## 9. 架构一句话

```
协议 vr-proto → 传输 vr-transport → 会话 vr-session → 角色（signal / agent / client）
                     ↑                    ↑
                  vr-net               vr-crypto
```

不引入 WebRTC，不依赖云账号，不牺牲可读性。
详见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

## 10. 适合谁

- **个人**：连家里的台式机、给父母修电脑、在外访问实验室机器。
- **小团队**：没有 VPN 的办公室，临时共享一台构建机。
- **企业内网**：完全离线部署，中继只在自己机房，审计只看元数据。
- **开发者**：需要一个可改、可嵌入、可自动化的远程桌面内核（CLI/SDK 齐全）。

---

## 11. 一句话总结

> Velarouter 把“远程桌面”还原成两件事：**把画面安全地送过去，把输入安全地送回来。**
> 其余的都是选择，不是必需。
